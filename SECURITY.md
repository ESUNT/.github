# ESUNT Security Policy

ESUNT welcomes responsible reports of security vulnerabilities in public ESUNT project materials and, when released, ESUNT software.

The availability and security-support status of any software will be stated in its individual repository. Do not assume that a documented design is a released or independently audited implementation.

## Reporting a vulnerability

**Do not open a public issue or discussion containing vulnerability details.**

If a repository offers GitHub's private **Report a vulnerability** option in its Security tab, use it. Otherwise, email **contact@esunt.com** with the subject **Confidential ESUNT Security Report**.

In your initial report, include:

- The affected repository, component, or document
- The relevant version or commit, if applicable
- A concise description of the suspected issue and its potential impact
- A way to contact you for follow-up

Do not email passwords, cryptographic keys, personal data, confidential ESUNT specifications, or sensitive exploit material. We can discuss a suitable private channel if more detail is needed.

## Coordinated disclosure

Please allow the project maintainers an opportunity to assess and address a valid security issue before publishing technical details.

Reporting an issue does not authorize testing against systems, devices, accounts, or data you do not own or have permission to assess.

## Other questions

For general development questions and collaboration inquiries, visit [esunt.org](https://www.esunt.org/) or contact **contact@esunt.com**.
